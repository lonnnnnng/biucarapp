# Biu Car 模拟器验收记录

## 验收环境

- AVD：`CASKA_1024x600`
- serial：`emulator-5554`
- Android：8.1 / API 27 / arm64-v8a
- 显示：1024×600 / 160 dpi
- 内存：1536MB

## 自动化检查

```zsh
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug --no-daemon --console=plain
```

覆盖 TV 二维码状态码映射、成功 Cookie 解析、缺失 `expires_in` 的兜底有效期、APPKey 签名和 WBI 签名稳定性。

## 已验证

- Debug APK 可安装并从 Launcher 启动，冷启动日志未出现 FATAL 或 ANR。
- 目标分辨率与密度正确，首页、媒体库历史页、账号页、二维码页和播放页无裁切或重叠。
- 首次使用且首页 UP 配置为空时，首页不请求默认推荐内容。
- TV 二维码申请接口返回成功；界面生成可扫描二维码并持续显示“等待扫码”。
- 系统状态栏和导航栏与应用深色主题一致。
- MediaController 能绑定 `CarPlaybackService`，空闲 PSS 约 58.5MB，无 Swap。
- 本地历史在未登录状态仍可进入，在线收藏和首页 UP 配置会明确引导登录。

## 扫码后的账号态验收

- 用户已在模拟器二维码页完成扫码确认，账号页显示“落叶回不来”，UID `103110588`，`/x/web-interface/nav` 复核为登录状态。
- 首页已恢复 `IM音乐故事汇` 配置并成功加载投稿；首页列表按发布时间倒序显示。
- “我创建的”返回默认收藏夹、`stm32`、`音频` 等真实目录；“我收藏的”返回 `私人尊享`、`华语热门歌手无损CD` 等真实合集。
- “B站历史”返回真实在线历史条目；“首页 UP”返回关注列表并正确标记已选 UP。
- “首页 UP”支持输入 UP 主名称或 UID 搜索，搜索结果与关注列表合并显示，搜索结果可以直接勾选并保存为首页来源。
- 首页、收藏夹和在线历史的内容列表已移除左侧播放箭头占位块，标题、作者、时间和右侧播放入口收紧到同一行布局。
- 音频目录第一条多 P 资源解析为 `P1 · 001. 夜曲-周杰伦`。锁屏通知和 MediaSession 标题均使用该分 P 标题，而不是主标题。
- 首次播放在 25 秒内进度从 `00:00` 增至 `00:23`，通知动作显示“Pause”，Room 保存 `44.3s / 226.9s`，缓存文件约 `6.3MB` 且状态为 `READY`。
- 关闭模拟器 Wi-Fi 后，从离线历史点击同一条目，使用 `file://` 缓存继续播放到 `02:12 / 03:46`，无网络请求、无崩溃；测试结束后已恢复 Wi-Fi。

## 本轮修复

- Bilibili CDN 拒绝旧版 `Android 8.1 / Chrome 61 Mobile` UA，改用桌面 Chrome UA 后媒体请求返回 `206 Partial Content`。
- 进度持久化协程曾在 IO 线程读取 ExoPlayer，修为主线程快照 Player 状态，避免 `Player is accessed on the wrong thread` 杀进程。
- `DefaultDataSource.Factory` 区分本地 `file://` 和在线 OkHttp 地址，离线历史不再把本地路径交给 OkHttp 导致 `Malformed URL`。

## 单 P 与多 P 连续播放验收

- 使用“音频”收藏夹第一条 `【一人一首成名曲】80.90后金曲回放 音乐中的清纯音符` 验证多 P：MediaSession 建立 `200` 项队列，首项显示 `P1 · 001. 夜曲-周杰伦`。
- 将 P1 拖到结尾后没有执行下一曲操作，ExoPlayer 自动进入 `P2 · 002. 海阔天空-Beyond`；MediaSession `active item id` 从 `0` 变为 `1`，队列仍为 `200` 项，播放状态为 `STATE_PLAYING`。
- Room 分别保存 `BV1SZ42127VH:1439359770` 和 `BV1SZ42127VH:1439359772`。P1 最终进度为 `226904/226904 ms`，P2 使用独立进度，证明自动转场没有把旧 P 进度写入新 cid。
- 使用“音频”收藏夹第二条 `【Hi-Res无损音质】滚石唱片精选《最好听10首合集》...` 验证单 P：旧的 200 项队列被替换，MediaSession `queue size=1`，标题不显示虚假的 `P1`。
- 两个场景均未出现 `FATAL EXCEPTION`、`PlaybackException`、`Player is accessed on the wrong thread` 或 `Malformed URL`。

## 播放列表与顺序控制验收

- 播放页已移除无实际内容的音符卡片，左侧常驻显示可滚动分 P 列表；1024×600 截图中列表与右侧播放控件均完整可见。
- 点击列表中的 `P3 · 003. 郑中基-无赖` 后，播放页标题和 MediaSession metadata 同步切换为 P3，`active item id=2`。
- 点击“下一曲”由 P3 切到 P4，点击“上一曲”由 P4 返回 P3。
- 点击播放顺序按钮后文案由“顺序播放”变为“单曲循环”；点击随机按钮后文案显示“单曲循环 · 随机”，图标状态同步变为开启。
- 播放列表数量会随渐进解析实时增长，未出现旧队列串入新资源或页面崩溃。
- 多 P 列表行不再显示代码生成的 `P1/P2` 序号列，只显示每个分 P 的实际标题；右侧上一曲、播放/暂停、下一曲、循环、随机按钮排列在同一行。
- 单 P 资源不显示播放列表，左侧显示 Bilibili 封面（封面加载失败时保留纯色占位），右侧仍保留同一排播放控制。
- 播放页已移除“后台播放已就绪”和缓存说明等状态文案。
- 单 P 控件验收：左侧显示实际封面，右侧五项控件水平等距排列，UI tree 中依次为“顺序播放”“上一曲”“暂停”“下一曲”“喜欢”，没有“播放顺序”说明文案。
- “喜欢”按钮已接入当前 `mediaId` 会话态，切换资源时不会继承上一项的喜欢状态；“我喜欢的”持久化列表待后续阶段实现。

首版范围之外的短信登录、视频播放、歌词、下载管理和多条音频并行缓存没有移植到车机端。

## 工具兼容说明

`android-emulator-install` skill 能正确构建并启动可见 AVD，但其设备识别只读取 `ro.boot.qemu.avd_name`。该 API 27 镜像只提供 `ro.kernel.qemu.avd_name=CASKA_1024x600`，因此脚本会误报 AVD 未出现。验收先由 skill 以 supervised 模式启动 AVD，再在已核对 serial 和内核 AVD 属性后对 `emulator-5554` 执行显式安装。
